name: generate-project-ui-snapshot
description: >
  分析当前前端项目源码，生成一个可交互、1:1 还原项目真实使用界面的单 HTML 文件
  （CSS/JS/图片全部内联），用于上传到网页后让 AI 审阅前端并提出修改建议。
  当用户说"生成项目快照"、"把项目打包成单个 HTML"、"导出可交互演示页"、
  "让 AI 评审我的前端"时使用本技能。

instructions: |
  # 项目界面快照生成器（Project UI Snapshot）

  ## 一、技能目标

  读取用户当前项目，产出一个单 HTML 文件（默认命名 `project-snapshot.html`），必须同时满足：

  - **1:1 还原**：布局、配色、字体、字号、间距、圆角、阴影、边框、动画曲线与真实项目完全一致；
  - **可交互**：所有按钮、链接、表单、弹窗、Tab、下拉菜单、抽屉、开关、分页都能正常点击操作，不是静态截图；
  - **零依赖**：CSS / JS / 图片 / 字体全部内联（base64 或内联 SVG），断网可打开，控制台零报错；
  - **便于 AI 审阅**：内置可开关的"审阅模式"，开启后高亮组件边界、标注组件名与尺寸，帮助 AI 精准定位可优化区域。

  > 核心原则：视觉与交互保真，而非代码保真。无论原项目是 React / Vue / Svelte / 原生，一律用「原生 HTML + 内联 CSS + 原生 JS」手工复刻界面，不尝试打包原代码。

  ## 二、执行流程

  ### 第 1 步：项目侦察（先读后写）

  按顺序读取并记录：

  1. `package.json` / `index.html` / 入口文件 → 判断框架（React / Vue / 原生 / 其他）与构建工具；
  2. 路由配置（react-router、vue-router、文件路由等）→ 列出全部页面/视图清单；
  3. 全局样式：`index.css` / `App.css` / `tailwind.config` / scss 变量 / CSS Variables → 提取设计令牌（主色、中性色、语义色、圆角、阴影、字号阶梯、行高、间距阶梯、断点）；
  4. 公共组件目录（`components/`、`layouts/`）→ 列出导航栏、侧边栏、卡片、按钮、表单控件的样式规范；
  5. 静态资源目录（`assets/`、`public/`）→ 登记需要内联的图片、图标、Logo、字体；
  6. 接口调用（fetch / axios / mock）→ 登记每个页面依赖的数据结构，准备假数据。

  侦察完成后，**先在回复中向用户输出简表确认**：

  > 页面清单 | 设计令牌摘要 | 需内联资产数量 | 需模拟的接口数量

  用户确认后再生成文件。

  ### 第 2 步：资产处理

  | 资产类型 | 处理方式 |
  |---|---|
  | 图片（png/jpg/webp） | 转 base64 内联到 `<img src="data:...">`；单张超过 300KB 时改用同尺寸内联 SVG 占位图（保留布局与配色氛围），并在审阅模式中标注"此处为占位图" |
  | 图标 | 一律转内联 SVG（`<svg>`），保留原颜色与尺寸 |
  | 字体 | 优先使用与原项目一致的字体栈回退方案；若原项目使用网络字体，用 fontsource CDN 的 `<link>` 引入（唯一允许的外部请求），并在文件头部注释说明 |
  | 第三方 UI 库样式 | 不引入库本身，手工复刻用到的那几个组件的样式 |

  ### 第 3 步：搭建单文件骨架

  生成的 HTML 必须遵循以下结构（按此顺序写入）：

  ```html
  <!DOCTYPE html>
  <html lang="zh-CN">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>{项目名} - 界面快照</title>
    <style>
      :root {
        --color-primary: #xxxxxx;
        --color-bg: #xxxxxx;
        --radius-md: 8px;
        --shadow-card: 0 2px 8px rgba(0,0,0,.08);
        --font-size-base: 14px;
        /* ……与原项目一一对应…… */
      }
    </style>
    <style> /* …… */ </style>
  </head>
  <body>
    <div id="app">
      <!-- ③ 各页面视图，默认仅显示首页 -->
      <nav>……</nav>
      <section class="view active" id="home">……</section>
      <section class="view" id="list">……</section>
    </div>
    <script>
      /* ④ 哈希路由：监听 hashchange，切换 .view.active，同步高亮导航 */
      /* ⑤ 交互逻辑：事件委托统一绑定，含弹窗、Tab、表单校验、下拉、开关等 */
      /* ⑥ Mock 数据与假接口：fetch 拦截或直接渲染假数据 */
      /* ⑦ 审阅模式：开关组件描边、显示标注、页面索引跳转 */
    </script>
  </body>
  </html>
```

  ### 第 4 步：交互还原规范（必须全部实现）

  - **路由跳转**：导航点击 → `location.hash = '#/list'` → 对应 `<section>` 显示，其余隐藏，导航高亮同步；浏览器前进后退可用；
  - **按钮**：所有可见按钮必须绑定行为——提交表单、打开弹窗、切换状态、Toast 提示，禁止死按钮；无法模拟的行为用 Toast 提示"演示环境：该操作已模拟成功"；
  - **表单**：输入、校验（必填/格式）、错误提示、提交成功反馈全流程可走通；
  - **弹窗/抽屉**：打开、关闭（遮罩点击 + 关闭按钮 + Esc 键）；
  - **Tab / 折叠面板 / 开关 / 下拉菜单**：状态切换即时生效；
  - **列表**：使用第 1 步登记的假数据渲染，搜索/筛选/分页若原项目有则必须可用；
  - **加载态**：原项目有 loading / skeleton 的，用 `setTimeout` 模拟 300–800ms 延迟展示；
  - **响应式**：按原项目断点写媒体查询，手机宽度下布局与真实项目一致；
  - **动画**：hover、过渡、弹窗进出场动画按原项目的 `transition` / `animation` 参数复刻。

  ### 第 5 步：审阅模式（本技能特色，默认关闭）

  右下角悬浮按钮"🔍 审阅模式"，开启后：

  - 每个组件块叠加半透明描边 + 左上角小标签（组件名，如 Card / NavBar / Form）；
  - 悬浮面板展开：当前页面名、组件总数、设计令牌速览（色板 + 字号阶梯）、"复制页面结构摘要"按钮（一键复制供粘贴给 AI 的结构化文本）；
  - 页面索引列表，点击直接跳转任意视图；
  - 关闭后完全隐藏，恢复纯净的 1:1 界面。

  ### 第 6 步：自验收清单（生成后逐条自检，未通过则修复）

  - [ ] 单文件，双击浏览器直接打开无报错、无 404、无外部请求（fontsource 除外）；
  - [ ] 与项目截图逐像素对比：首屏布局、配色、字体、间距一致；
  - [ ] 页面清单中每个视图都能通过导航或 hash 直达；
  - [ ] 每个按钮/链接点击后有真实反馈，无死交互；
  - [ ] 表单完整走通"输入 → 校验 → 提交 → 成功提示"；
  - [ ] 375px 宽度下布局与原项目移动端表现一致；
  - [ ] 审阅模式可正常开关，关闭后无任何残留元素；
  - [ ] 控制台执行 `document.querySelectorAll('.view').length` 输出值等于页面清单数量。

  ### 第 7 步：交付说明

  生成文件后，向用户说明：

  1. 文件保存为 `project-snapshot.html`，直接上传任意静态托管（GitHub Pages / Netlify / 对象存储）即可；
  2. 给 AI 审阅时的推荐用法：发送链接 + 一句话需求（如"请从信息层级、配色、留白、移动端适配四个维度提出修改建议"），需要精准定位时开启审阅模式并截图；
  3. 如项目后续迭代，重新运行本技能即可刷新快照。

  ## 三、特殊情况处理

| 情况                        | 方案                                                         |
| --------------------------- | ------------------------------------------------------------ |
| 页面过多（>15 个视图）      | 与用户确认优先级，先做核心流程（首页 + 主业务流 + 登录/注册），其余视图在审阅模式索引中标注"未包含" |
| 需要登录态                  | 内置假登录页，任意账号密码均可"登录"，`localStorage` 存假 token，还原登录前后界面差异 |
| 强依赖后端数据              | 按接口返回结构写死 3–8 条高仿真假数据，字段名与原项目一致    |
| 原项目使用 Tailwind         | 不引 CDN，把用到的工具类编译成等价的原生 CSS 写入 `<style>`  |
| 图表（ECharts/Chart.js 等） | 允许通过 CDN 引入对应图表库（唯一例外），用假数据渲染真实图表；若追求绝对离线则手绘 SVG 近似图 |
| 文件超过 3MB                | 压缩 base64 图片、合并重复样式、向用户报告体积构成           |

  ## 四、禁止事项

  - ❌ 输出多个文件（必须单 HTML）；
  - ❌ 使用 `alert()` 充当交互反馈（用项目原有 Toast 风格复刻）；
  - ❌ 留下 `onclick=""` 空实现或 `href="#"` 死链接；
  - ❌ 自行"美化"或改动原项目界面（保真优先，修改建议交给审阅 AI 提）；
  - ❌ 在快照中保留真实密钥、真实接口地址、用户隐私数据（一律替换为 mock）。
